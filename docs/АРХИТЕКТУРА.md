# «ПЛЕЧО» — техническая архитектура

Документ фиксирует решения, которые дорого менять потом. Всё остальное решается
по ходу.

---

## 1. Главное решение: симуляция отдельно от всего

`src/sim/` — чистый TypeScript. **Ноль импортов React, Three.js, DOM, браузерных
API.** Запускается в Node без окружения.

Из этого следует всё остальное:

- **Тесты на экономику** без браузера. Прогон тысячи игровых лет за секунды для
  настройки баланса
- **Детерминированность.** Одно и то же состояние плюс один и тот же сид дают
  один и тот же результат. Баг воспроизводится по сохранению
- **Сохранения** — это `JSON.stringify(state)`, без отдельного слоя сериализации
- **Ускорение времени** — просто больше тиков за кадр, никакой особой логики
- **Агент проверяет себя** прогоном симуляции, не открывая браузер

Нарушение этой границы — самая дорогая ошибка в проекте. Если в `sim/` попадёт
хоть один `useState`, всё вышеперечисленное отваливается.

## 3. Модель состояния

Всё состояние игры — одна сериализуемая структура. Никакого состояния вне неё.

```ts
type GameState = {
  seed: number
  tick: number                    // сколько тиков прошло с начала
  date: GameDate                  // производная от tick, для удобства

  world: {
    cities: Record<CityId, City>
    industries: Record<IndustryId, Industry>
    edges: Edge[]                 // рёбра графа дорог
  }

  companies: Record<CompanyId, Company>   // игрок и конкуренты — одна структура
  playerId: CompanyId

  market: {
    fuelPrice: number
    rates: Record<CargoType, number>
  }

  events: GameEvent[]             // лента: поломки, штрафы, рост города
}
```

**Игрок и конкуренты — одинаковые структуры.** Это принципиально: вся логика
компании пишется один раз и работает для всех. Разница только в том, кто
принимает решения — человек, скрипт или модель.

```ts
type Company = {
  id: CompanyId
  name: string
  money: number
  debt: Loan[]
  vehicles: Record<VehicleId, Vehicle>
  drivers: Record<DriverId, Driver>
  lines: Record<LineId, Line>
  buildings: Building[]           // терминалы, склады, АЗС, ремзоны
  reputation: Record<RegionId, number>
  controller: 'human' | 'scripted' | 'llm'
}

type Line = {
  id: LineId
  name: string
  stops: Stop[]                   // замкнутая последовательность
  assignedVehicles: VehicleId[]
}

type Stop = {
  nodeId: CityId | IndustryId | BuildingId
  unload: CargoType[]
  load: CargoType[]
}

type Vehicle = {
  id: VehicleId
  model: VehicleModelId
  trailer: TrailerType | null
  lineId: LineId | null
  driverId: DriverId | null

  // положение
  edgeId: EdgeId | null           // на каком ребре едет
  progress: number                // 0..1 по ребру
  stopIndex: number               // к какой остановке линии направляется

  cargo: { type: CargoType, amount: number } | null
  fuel: number
  wear: number                    // 0..1, ресурс
  odometer: number

  // статистика для метрик
  loadedKm: number
  emptyKm: number
}

type Industry = {
  id: IndustryId
  type: IndustryType
  cityId: CityId
  stock: Record<CargoType, number>     // склад входов и выходов
  productionRate: number                // текущий темп, зависит от снабжения
}
```

Метрика порожнего пробега считается из `loadedKm` и `emptyKm` — она не хранится
отдельно, а выводится. Общее правило: **производные значения не хранятся**, чтобы
не рассинхронизировались.

## 4. Тик симуляции

Фиксированный шаг. Один тик = **15 игровых минут**. Порядок фаз строгий, менять
его нельзя без последствий.

```ts
function tick(state: GameState): GameState
```

1. **Время.** `tick++`, пересчёт даты, сезона, времени суток
2. **Производство.** Каждое предприятие: есть входы → потребить, произвести
   выход на склад. Нет входов или склад выхода переполнен → темп падает
3. **Движение.** Каждая машина в пути: продвинуться по ребру с учётом скорости,
   качества дороги, загрузки, погоды, навыка водителя. Сжечь топливо. Накопить
   износ и километраж — в `loadedKm` или `emptyKm` в зависимости от груза
4. **Прибытие.** Машина дошла до остановки → выгрузка, погрузка по правилам
   линии, расчёт денег, постановка на следующее ребро. Если терминал занят —
   в очередь
5. **Потребление.** Города потребляют со складов, растут или сжимаются
6. **Финансы.** По расписанию: зарплаты, ТО, платежи по кредитам, налоги.
   Проверка банкротства
7. **Рынок.** Пересчёт цен на топливо и ставок
8. **Решения ИИ.** Раз в игровой месяц — скриптовые конкуренты каждый тик дёшево,
   LLM асинхронно (см. ниже)
9. **События.** Поломки, штрафы, аварии — с использованием сидированного ГПСЧ

**Скорость игры** влияет только на число тиков за кадр реального времени, не на
логику. Пауза = ноль тиков.

Предлагаемая шкала: ×1 — игровые сутки примерно за 20 секунд. Требует подгонки на
плейтестах, но масштаб такой: рейс Москва → Тула виден несколько секунд, игровой
год проходит за пару часов. Финальные числа настроим прогоном.

## 5. Мир как граф

Города и предприятия — узлы. Дороги — рёбра.

```ts
type Edge = {
  id: EdgeId
  from: NodeId
  to: NodeId
  km: number
  class: 'federal' | 'regional' | 'local'
  quality: number        // 0..1, влияет на скорость и износ
  axleLimit: number      // тонн, весной снижается
  load: number           // текущая загрузка, влияет на скорость всех
}
```

**Поиск пути** — Дейкстра по весу «время в пути». Веса меняются медленно
(качество, сезон, загрузка), поэтому пути кэшируются и пересчитываются только при
изменении графа или раз в игровой день.

**Данные берём вручную, не парсим.** Реальные города с координатами и населением
плюс граф основных федеральных трасс — М-1, М-2, М-4, М-5, М-7, М-11 и
региональные связки. Для ЦФО это примерно 10 узлов и 15 рёбер, набивается за час
и получается точнее любого автоматического импорта. Расширяем по регионам.

**Проекция** широта/долгота → плоскость: равнопромежуточная с масштабом по
широте. Для страны такого размера искажения приемлемы, а формула тривиальная.

## 6. Производственные цепочки

Рецепты — данные, не код.

```ts
type Recipe = {
  industryType: IndustryType
  inputs: { type: CargoType, perUnit: number }[]
  output: { type: CargoType, perUnit: number }
  baseRate: number        // единиц выхода за тик при полном снабжении
}
```

Пример:

```ts
{ industryType: 'мукомольный',
  inputs: [{ type: 'зерно', perUnit: 1.2 }],
  output: { type: 'мука', perUnit: 1 },
  baseRate: 4 }
```

Правила работы предприятия:

- Хватает входов → производит на `baseRate`
- Не хватает → темп падает пропорционально дефициту
- Склад выхода полон → темп падает до нуля, предприятие «задыхается»
- Простой дольше N дней → предприятие деградирует, а при долгом простое закрывается

Последнее — важно. Это то, что делает бездействие игрока наказуемым и создаёт
ощущение живого мира.

## 7. Куда подключается LLM

Модель **не находится внутри тика**. Тик синхронный и детерминированный, сетевой
вызов туда пускать нельзя.

Схема:

1. Раз в игровой месяц симуляция кладёт в очередь запрос: снимок состояния для
   конкурента
2. Асинхронный воркер собирает промпт, зовёт Gemini, разбирает ответ в набор
   **команд** (`buildTerminal`, `createLine`, `buyVehicle`, `poachDriver`, …)
3. Команды складываются в очередь состояния и применяются на следующем тике

Так симуляция остаётся детерминированной: ответ модели становится частью входных
данных, а не побочным эффектом внутри тика. Сохранение с записанными командами
воспроизводится один в один.

**Фолбэк.** Нет сети, превышен лимит, невалидный ответ — команды берутся у
скриптового конкурента. Игра не замечает разницы.

Команды строго типизированы и валидируются. Модель не исполняет произвольный код
и не меняет состояние напрямую — только предлагает действия из фиксированного
набора, каждое из которых проверяется на легальность теми же правилами, что и
действия игрока.

## 8. Рендер

R3F читает состояние и отрисовывает. Никакой игровой логики в компонентах.

**Интерполяция.** Тик редкий, кадры частые. Машины движутся плавно за счёт
интерполяции `progress` между последним и предыдущим тиком. Хранятся два
последних снимка позиций.

**Инстансинг.** Машин на карте могут быть сотни. Все одного класса рисуются одним
`InstancedMesh`. Города и здания — тоже.

**Геометрия из кода.** Дороги — `TubeGeometry` по сплайну через точки ребра.
Города — процедурные кластеры коробок с сидом от `cityId`, чтобы силуэт был
стабильным между сессиями. Предприятия — узнаваемые силуэты из примитивов.

## 9. Тесты

Основная ценность чистой симуляции.

- **Юнит** на каждое правило: производство при дефиците, износ, расход топлива,
  начисление денег
- **Свойства** экономики: при разумной игре компания не банкротится за год; при
  бездействии банкротится; сумма денег в системе не растёт из ниоткуда
- **Прогоны** на баланс: тысяча игровых лет с ботом-игроком, сбор статистики —
  сколько живут компании, где ломается экономика
- **Playwright** — только на интерфейс и на то, что сцена рендерится без ошибок

Экономика тестируется без React и без браузера. Это позволяет мне править баланс
и сразу видеть результат, не открывая игру.

## 10. Что решаем позже

Явно откладываем, чтобы не проектировать вслепую:

- Точная шкала времени — подгоняется на плейтестах
- Формулы баланса — выводятся прогонами, а не на бумаге
- Формат сохранений в localStorage против файла
- Мультиплеер — не проектируем вообще, но структура состояния его не запрещает
